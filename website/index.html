THE PROBLEM

The Cost of Context Switching

When you step away from a complex task, mental cache evaporates. Reconstructing what was modified, which branch was active, and which commands were run drains developer energy.

WITHOUT LIFELOG

Manual Mental Archaeology

  • Forgotten WIP: Digging through git status, uncommitted diffs, and untracked stashes.
  • Lost Terminal History: Reverse-i-searching shell history to find exact test flags and environment variables.
  • Cloud Surveillance: Commercial tools upload your private keystrokes and screen recordings to third-party AI clouds.
  • 23-Minute Penalty: Recovering deep engineering flow state after an interruption takes nearly half an hour.
WITH LIFELOG

Instant Resumption Replay

  • One-Click Report: Click "Resumption" or run lifelog resume to get an instant synthesis of your exact last session.
  • Observed Evidence: See exact file modification timestamps, active branch HEAD, and sanitized command metadata.
  • Zero Keystroke / Zero Screen Capture: Pure metadata observation. No video, no OCR, no remote servers, no surveillance.
  • Zero Seconds Wasted: Pick up directly in flow without mental fatigue or reconstructed guesswork.
ENGINEERING ARCHITECTURE

How LIFELOG Synthesizes Memory

Built with an authenticated local daemon and pure-Go zero-CGO SQLite engine. Data flows through a strict privacy boundary before persisting locally.

1

Silent Observers

Event-driven observers track file modifications (fs_poll), local Git branch changes, opt-in terminal runs, and macOS foreground app activations.

NSWorkspaceDidActivate + DistributedNotification
2

Privacy Sanitization

Deterministic regex sanitizers mask API keys, tokens, and bearer credentials. Credential tools (op, security) are omitted. Zero file content is read.

[REDACTED] flags + zero stdout capture
3

SQLite WAL Persistence

Records persist into modernc.org/sqlite schema v9 with immediate write-ahead logging (WAL mode), transactional migrations, and real-time FTS5 triggers.

_journal_mode=WAL & _txlock=immediate
4

Session Clustering

Inactivity gap clustering (30m threshold) partitions disjoint events into cohesive, logical work sessions with start/end boundaries and primary focal directories.

Threshold: gap > 30m => New Session
5

FTS5 Full-Text Search

Unified BM25 search index across files, Git commits, terminal commands, and app sessions. Accessible via global ⌘K in under 1 millisecond.

search_index triggers on insert/update/delete
6

Synthesis & Resumption

Generates Markdown and JSON resumption packages separating Observed ground truth from Derived context and Unavailable privacy boundaries.

lifelog resume => Portable Resumption Report
CORE CAPABILITIES

Designed for Engineers Who Value Privacy

Professional, restrained, and meticulously engineered. No bloated webviews, no invasive trackers, and zero AI slop.

100% Local-First & Zero Cloud

All activity data resides in ~/Library/Application Support/LifeLog. Zero cloud syncing, zero remote API calls, and zero external telemetry.

Zero File Content Snooping

Filesystem observation records metadata only (path, size, timestamp, event type). File contents, patches, and code diffs are never inspected or persisted.

Native App & System Tracking

Records active foreground applications and system sleep/wake/lock transitions via native macOS notifications. Open sessions are auto-finalized upon screen lock.

Deterministic Secret Redaction

Command flags containing tokens, passwords, and API keys are automatically sanitized into [REDACTED] before reaching storage.

Automated Retention Policies

Configure automatic data cleanup presets (7d, 30d, 90d, 365d, or forever). Cleanup transactions purge expired records across tables and cascade to the search index.

Full User Data Portability

Export your entire activity history into a clean, structured JSON document conforming to schema lifelog-export-v1. Written with restricted 0600 file permissions.

MACOS GATEKEEPER GUIDE

Seeing "Damaged and can't be opened"?

Because LIFELOG is free, open-source software built by independent engineers without a $99/year commercial Apple Developer ID certificate, macOS automatically quarantines disk images downloaded via web browsers (Brave, Chrome, Safari).

The 1-Second Fix: Drag LifeLog.app to your /Applications folder, open Terminal, and run:

xattr -cr /Applications/LifeLog.app
This command clears the macOS quarantine attribute set by your browser, allowing the verified ad-hoc code signature to run natively.

SECURITY HARDENING AUDIT

Engineered to Resist Compromise

LIFELOG is built with defense-in-depth principles. Because the app stores memory of your engineering work, the communication architecture is protected against unauthorized local and remote access.

Unix Domain Socket with 0600 Permissions: No open TCP ports. Browser tabs cannot make HTTP requests to connect to or extract data from the daemon.
Timing-Attack Resistant Handshake Token: All IPC connections require an ephemeral handshake token verified using crypto/subtle.ConstantTimeCompare.
Strict Electron Sandboxing & Context Isolation: Renderer has zero access to Node.js APIs or arbitrary filesystem commands. Minimal typed bridge only.
All Navigation & Permissions Blocked: External window navigation is prevented. Microphone, camera, and geolocation permissions are rejected by policy.
Pure-Go Zero-CGO SQLite Engine: Compiled with modernc.org/sqlite without CGO, eliminating buffer overflow risks in unmanaged C extensions.
Strict Path Escaping & Export Isolation: Export destinations within the internal data directory are rejected to prevent self-overwriting attacks.
FREQUENTLY ASKED QUESTIONS

Common Questions & Answers

Everything you need to know about LIFELOG's privacy architecture and performance.

Why is LIFELOG 100% local-first?
Software engineers handle proprietary source code, internal API credentials, and sensitive architectural context. Storing activity in the cloud introduces compliance violations and security risks. By remaining strictly local-first with pure-Go SQLite WAL storage, your computer memory belongs exclusively to you.
Can LIFELOG see my passwords, API keys, or code contents?
No. The filesystem observer records metadata only (path, size in bytes, modification time, event type). File contents and diffs are never read or stored. When commands are recorded via the terminal runner, all flags containing tokens, passwords, and API keys are automatically sanitized into [REDACTED] before reaching disk.
How much battery and CPU does LIFELOG consume in the background?
0.0% CPU when idle. LIFELOG does not poll the screen, capture video frames, or run OCR loops. Application and system state changes are driven entirely by native macOS event notifications (NSWorkspaceDidActivateApplicationNotification, DistributedNotificationCenter). Combined memory usage is approximately 26 MB RSS.
Why does macOS Gatekeeper warn on first download?
Apple requires open-source software developers to enroll in the paid Apple Developer Program ($99/year) to notarize applications. Unsigned or ad-hoc signed open-source binaries downloaded via web browsers are quarantined by Gatekeeper. Running xattr -cr /Applications/LifeLog.app clears the quarantine flag immediately.
How do I delete or export my recorded data?
Open Settings in the desktop app or run lifelog export to export your entire history in versioned JSON format. You can also configure automated retention cleanup (e.g. 30 days) or immediately purge specific activity sources from Settings > Data Management.
